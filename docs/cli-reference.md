## agent_board.py

```text
usage: agent_board.py [-h] [--repo REPO]
                      {message-changes,capabilities,init,maintenance,post,inbox,read,ack,status,ticket,actor,roadmap} ...

Shared, file-backed coordination board for masters and human operators. The
runtime lives below ``git rev-parse --git-common-dir`` and is therefore shared
by every worktree while remaining outside the versioned working tree. Project
configuration controls operational identities and message participants. The
actor registry adds ticket roles and master/subagent relationships.

positional arguments:
  {message-changes,capabilities,init,maintenance,post,inbox,read,ack,status,ticket,actor,roadmap}
    message-changes     read resumable immutable messages
    capabilities        print machine-readable commands and conventions
    init                create the shared runtime directories
    maintenance         remove stale legacy lock dotfiles left beside their
                        target
    post                create an immutable Markdown message
    inbox               list messages addressed to one participant
    read                print one immutable Markdown message
    ack                 acknowledge a message in a separate file
    status              publish or list master status
    ticket              create, list, and drive tickets through their
                        lifecycle
    actor               register or list per-project actors (roles,
                        master/subagent links)
    roadmap             list, get, or update roadmap items

options:
  -h, --help            show this help message and exit
  --repo REPO           worktree used to resolve the Git common dir
```

## agent_board.py ticket

```text
usage: agent_board.py ticket [-h]
                             {create,upsert,assign,heartbeat,transition,comment,worklog,review,done,dep-add,claim,handoff,dep-remove,changes,cache-verify,cache-rebuild,recover,list,get,tree,critical-path,metrics,wip,archive,export,verify} ...

positional arguments:
  {create,upsert,assign,heartbeat,transition,comment,worklog,review,done,dep-add,claim,handoff,dep-remove,changes,cache-verify,cache-rebuild,recover,list,get,tree,critical-path,metrics,wip,archive,export,verify}
    create              create a new ticket
    upsert              update mutable fields of an existing ticket
    assign              self-assign (or reassign) a ticket and open a lease
    heartbeat           extend the lease held by the actor
    transition          move a ticket to a new stage (not DONE; see done)
    comment             attach a comment to a ticket
    worklog             record evidence pointers: commit, test, or artifact
    review              record an owning-master review verdict
    done                mark a reviewed, unblocked ticket DONE
    dep-add             add a typed dependency edge
    claim               atomically claim unleased work
    handoff             atomically deliver evidence and transfer work
    dep-remove          remove a dependency and its reciprocal edge
    changes             read resumable ticket events
    cache-verify        verify the rebuildable ticket projection
    cache-rebuild       rebuild ticket projection from event logs
    recover             back up and remove a damaged final event record
    list                list tickets
    get                 print one ticket's current state
    tree                print the parent/child ticket tree
    critical-path       print the longest open BLOCKED_BY chain
    metrics             print throughput/time-in-stage/reopen metrics
    wip                 print work-in-progress by assignee
    archive             archive a DONE or CANCELLED ticket
    export              render one ticket as standalone Markdown
    verify              recompute one ticket's hash chain and report drift

options:
  -h, --help            show this help message and exit
```

## agent_board_watch.py

```text
usage: agent_board_watch.py [-h] --repo REPO --actor ACTOR
                            [--cursor-file CURSOR_FILE]

Blocking, native filesystem notifications bridged to flushed NDJSON. The
harness owns this long-lived subprocess and consumes stdout. Successful writes
are transport delivery, not acknowledgement by an agent. Deduplicate message
IDs when restarting: a crash between flush and cursor replacement can replay a
page.

options:
  -h, --help            show this help message and exit
  --repo REPO
  --actor ACTOR
  --cursor-file CURSOR_FILE
```
